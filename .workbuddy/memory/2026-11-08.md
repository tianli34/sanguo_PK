## 网页版：回退与时间轴定位（v=7）

- 结论：战报是“只进不退”的事件队列，但每个事件自带 `before/after` 快照，所以回退＝**按快照重建**到第 index 个事件之前，而不是倒放动画。
- `app.js` 新增：
  - `statesAtIndex(limit)` 汇总到该点的双方快照；`readProgress(limit)` 推导回合/刻度/最近描述；`paintProgressLabels(target)` 写标签与 `setAction`。
  - `previewTo(index)` 拖动时的轻量预览（只刷数值条与标签，不重建战报列表）；`rebuildTo(index)` 完整重建（面板 + 战报 + 标签 + 结果层 + 控制按钮），并用 `suppressBarFlash` 抑制重建过程中的阶段闪亮。
  - `stepBack()` 供「上一步」按钮；`skipToResult()` 改为 `rebuildTo(events.length)` 的薄封装。
  - 播放循环里每事件补 `updateControls()`，否则「上一步」在播放中仍是 disabled。
- 时间轴：`#timeline` 变 `role="slider"`，`pointerdown/move/up` 拖动（pointerdown 即 `pausePlayback()`，`setPointerCapture` 用 try/catch 防合成事件异常），另加 `click` 兜底（300ms 内忽略，避免与拖动重复重建）；`←/→` 逐条后退/前进（document 级监听，跳过输入框/弹窗，靠 `defaultPrevented` 防止与时间轴自身监听重复触发）。
- `styles.css`：`.timeline` 4px→10px 可点轨道 + `.timeline-knob` 圆点（hover/拖动/聚焦时显形）+ `::before{inset:-7px 0}` 透明扩展热区。
- `index.html`：新增 `#back-button`「上一步」，版本 `?v=7`。
- 调试经验：CUA 点击偶尔打不中细元素，用同源 iframe 探针打印 `elementFromPoint` 与 `getBoundingClientRect` 最靠谱；合成 `new PointerEvent(...)` 可以直接验证拖动链路（本例 2 → 352 事件）。
